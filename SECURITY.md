# Security Policy / 安全政策

## Reporting a vulnerability / 报告安全问题

请不要在公开 Issue 中发布尚未修复的漏洞、利用代码、访问令牌、签名密钥或用户数据。

Please do not disclose an unpatched vulnerability, exploit code, access token, signing key, or private user data in a public issue.

如果仓库启用了 GitHub 的私密漏洞报告，请通过仓库的 **Security** 页面选择 **Report a vulnerability** 提交。若该功能不可用，请通过仓库主页列出的维护者私下联系方式联系维护者，并注明这是安全问题。

When available, use GitHub private vulnerability reporting from the repository's **Security** page. If it is not available, contact a maintainer through a private channel listed on the repository page and clearly mark the report as security-sensitive.

报告中请尽量包含：

- 受影响的版本或 commit；
- 设备、Android、LSPosed 及游戏版本；
- 可重复的步骤或最小复现样例；
- 预期影响范围；
- 已脱敏的日志或崩溃信息。

Please include the affected version or commit, device and platform versions, reproducible steps or a minimal reproduction, impact, and redacted logs where possible.

## Supported versions / 支持范围

优先处理当前默认分支和最新发布版本中的安全问题。旧版本是否修复，需要结合漏洞影响和维护成本单独评估。

Security issues in the default branch and latest release receive priority. Fixes for older versions are evaluated case by case.

## Disclosure / 信息披露

维护者会先确认问题、评估影响并协调修复与披露时间。请在问题得到确认前避免公开传播细节。

Maintainers will validate the report, assess its impact, and coordinate remediation and disclosure. Please avoid public disclosure of details before the issue has been assessed.
