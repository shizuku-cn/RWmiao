# 房间游戏选项扩展 p4

## 本阶段

- 版本：`0.11-p4`
- 目标：缩窄 M3 对话框、增加可用内容高度，使用等宽双列布局。
- 底部“取消 / 应用”操作栏保持固定，内容区独立滚动。

## 面板布局

左列：

1. 初始资金
2. 初始单位
3. 战争迷雾
4. AI 难度
5. 团队布局
6. 资金增长倍率

右列：

1. 房间人数上限
2. 单位上限
3. 禁用核弹
4. 允许共享控制
5. 全局 Ban 单位

初始资金、初始单位、战争迷雾、AI 难度和团队布局改为 M3 选择器，不再使用输入框。人数、单位上限和资金倍率仍是可校验的自定义数值输入。

## Ban 单位链路

旧实现直接枚举 `game.units.cj.values()`，会把建筑、资源和占位类型混入列表。p4 改为枚举各单位类型的真实生产动作列表，仅提取 `game.units.a.l` 队列生产动作的 `h()` 目标，因此列表来源与游戏生产页一致。

房主应用后保存 Ban 集合。命令校验点 `gameFramework.e.i()` 负责提前拒绝，最终执行点 `gameFramework.e.h()` 再做一次拦截；这样未修改客户端发送生产命令时，也会在房主侧被拒绝。

## 单位上限链路

原版在 `gameFramework.j.ae.a(boolean)` 中会从 `SettingsEngine.teamUnitCapHostedGame` 重载 `ay/az`，进入游戏时 `game.i.a(boolean, boolean, int)` 又会把网络值复制到实际的 `by/bz`。p4 在这两个生命周期点重新写入已应用的上限，避免只修改房间界面字段后进入对局恢复原值。

## 构建验证

- `:app:assembleRelease`：成功。
- APK 签名与 SHA-256 需要在复制到发布目录后执行最终验证。
- 当前没有连接 Android/ADB 设备，因此 Ban 实际拒绝生产和进局后的上限效果仍需真机联机复测。
